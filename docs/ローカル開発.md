# ローカル開発ガイド

ローカルで動かしたBotをDiscordに繋いで動作確認するための手順。Discordのスラッシュコマンドはインターネット経由でWebhookが飛んでくるため、ローカルサーバーをトンネルで外部公開する必要がある。

## 全体像

```
Discord ──(スラッシュコマンド実行)──▶ Discordのサーバー
   └─(HTTPS Webhook)─▶ トンネル(cloudflared等) ─▶ localhost:8787 (wrangler dev)
```

---

## 前提: Discord アプリの用意

[Discord Developer Portal](https://discord.com/developers/applications) で以下を用意する。

- アプリを作成（または既存を使用）
- **Application ID** と **Public Key**（General Information タブ）を控える
- **Bot Token**（Bot タブ）を控える
- Botをテスト用サーバーに招待する
  - OAuth2 > URL Generator で `applications.commands` + `bot` スコープを選択し、生成されたURLから招待

---

## 手順

### 1. ローカル secrets を設定

`apps/bot/.dev.vars` を作成する（`.gitignore` 済みなのでコミットされない）。

```
DISCORD_TOKEN=（Bot Token）
DISCORD_PUBLIC_KEY=（Public Key）
DISCORD_APPLICATION_ID=（Application ID）
DISCORD_TEST_GUILD_ID=（テストサーバーID）
```

> `DISCORD_PUBLIC_KEY` が正しくないと、後述のInteractions Endpoint検証（手順6）で弾かれる。
> `DISCORD_TEST_GUILD_ID` はコマンド登録（手順3）で使う。ここに書いておけば登録コマンド実行時に環境変数を毎回並べる必要がない。

### 2. D1マイグレーションをローカルに適用

テーブルがない状態では動かないので、初回とスキーマ変更時に実行する。

```
cd apps/bot
bunx wrangler d1 migrations apply quiz-bot-db --local
```

### 3. スラッシュコマンドをDiscordに登録

コマンド定義（`apps/bot/src/commands/quizCommand.ts`）をDiscord側へ同期する。`register` スクリプトは `.dev.vars` を `--env-file` で読み込むため、手順1で `.dev.vars` を設定していれば以下だけでよい。

```
cd apps/bot
bun run register
```

- `.dev.vars` に `DISCORD_TEST_GUILD_ID` があるとそのサーバーだけに**即時反映**される
- `DISCORD_TEST_GUILD_ID` が未設定だとグローバル登録となり、反映に最大1時間かかる
- コマンド定義を変更したときだけ再実行すればよい（毎回は不要）

### 4. ローカルサーバーを起動

```
bun run dev:bot        # ルートから。内部で apps/bot の wrangler dev を実行
```

`http://localhost:8787` で起動する。

### 5. トンネルで外部公開

別ターミナルで、localhostをHTTPSで公開する。cloudflaredのクイックトンネルが手軽（未インストールなら `brew install cloudflared`。ngrokでも可）。

```
cloudflared tunnel --url http://localhost:8787
```

`https://xxxx.trycloudflare.com` のようなURLが発行される。

> **クイックトンネルのURLは使い捨て**。プロセスを落とすとURLは即座に無効化され、再起動すると別のURLになる。URLを固定したい場合は末尾「名前付きトンネル」を参照。

### 6. Interactions Endpoint URL を登録

Discord Developer Portal > General Information > **Interactions Endpoint URL** に手順5のURLを貼る。

```
https://xxxx.trycloudflare.com/
```

保存時にDiscordが検証リクエスト（PING）を送るため、**wrangler devとトンネルが両方起動している状態**で保存すること。署名検証が通れば保存に成功する。

### 7. Discordで試す

テストサーバーでスラッシュコマンドを実行すると、ローカルのWorkerが応答する。

```
/quiz create title:テストクイズ
/quiz add-question quiz_id:xxx type:free_text body:日本の首都は？ answers:東京,とうきょう,Tokyo
/quiz add-question quiz_id:xxx type:true_false body:富士山は日本一高い山だ answers:○
/quiz play
```

`/quiz play`（引数なし）を実行すると出題設定GUIが表示される。プルダウンでクイズを選び、出題数（モーダル入力）とプレイ形式（1人/みんなで早押し）を設定して **Play ボタン** で出題を開始する。回答は出題形式に応じたボタン（自由記述は「回答する」ボタン→モーダル）で行う。仕様の詳細は [要件定義.md](要件定義.md) の「2.2 クイズ出題」を参照。

> **○×クイズの正解値**: `true_false` の設問はボタンが `○` / `×` を送信するため、`answers` は `○` または `×` で登録すること。

## Web API / フロントエンドのローカル起動

Botとは独立して動かせる。

```
bun run dev:api    # apps/api（Hono）。localhost:8787 で起動するのでBotとポートが被る場合は --port で変更
bun run dev:web    # apps/web（Vite）。localhost:5173 で起動
```

- `apps/api/.dev.vars` に `DISCORD_CLIENT_ID` / `DISCORD_CLIENT_SECRET`（OAuth2用）を設定する
- Web側は `VITE_API_ORIGIN` でAPIのオリジンを指定できる（未指定時は `http://localhost:8788`）
- BotとAPIを同時に起動する場合はポート衝突に注意（どちらかを `wrangler dev --port` で変更する）

---

## よくあるつまずき

| 症状 | 原因・対処 |
|---|---|
| 手順6のEndpoint検証に失敗する | `.dev.vars` の `DISCORD_PUBLIC_KEY` の値、またはトンネル/devサーバーの起動状態を確認 |
| コマンドがDiscordに出てこない | 手順3の `register` 未実行、またはグローバル登録で反映待ち（`DISCORD_TEST_GUILD_ID` を付けて再実行） |
| `no such table` エラー | 手順2のマイグレーション未適用 |
| トンネルURLが変わって繋がらない | クイックトンネルはURL使い捨て。再起動したら手順6のURLを貼り直す |

---

## 補足: 名前付きトンネル（URLを固定したい場合）

毎回URLが変わって手順6の貼り直しが面倒な場合、Cloudflareアカウントと自分のドメインがあれば固定URLにできる。

```
cloudflared tunnel login
cloudflared tunnel create quiz-bot-dev
cloudflared tunnel route dns quiz-bot-dev dev.example.com
```

- URLが固定されるため、サーバーを落として再起動しても同じURLで繋がる
- Cloudflare側にトンネル設定が残る（`cloudflared tunnel delete` で明示削除するまで）

| | クイックトンネル | 名前付きトンネル |
|---|---|---|
| URL | 毎回変わる・使い捨て | 固定 |
| 事前準備 | 不要 | ログイン + ドメイン必要 |
| 用途 | 単発の動作確認 | 継続的な開発 |
