# アーキテクチャ構成

[要件定義.md](./要件定義.md) を実現するためのシステム構成方針。

## 方針

Bot（Discord Hono）と Web用API（Hono）を独立した Cloudflare Worker として運用しつつ、両者が使うビジネスロジック（クイズCRUD・権限チェック・出題・正誤判定・統計集計・レート制限）は `core` パッケージとして共有ライブラリ化し、それぞれの Worker から直接 import する。HTTPで叩き合う共通APIとしては構成しない。

### この方針を採る理由

- Bot・Web APIともに Cloudflare Workers 上で動き、同じ D1 データベースにバインドする構成になるため、あえてHTTP（またはService Bindings）を挟む必要がない
- 共有ライブラリとして直接importすることで、関数呼び出しのレイテンシ・追加コストがゼロになる
- TypeScriptの型（Quiz, Question, Attempt など）とロジックを1箇所に集約でき、境界でのシリアライズ/デシリアライズのズレが発生しない
- 権限チェックをサービス層の関数内に内包させることで、呼び出し側（Bot/Web両方）での実装漏れを防げる

## モノレポ構成（案）

```
apps/
  bot/            # Discord Hono Worker（Discord Interactionの処理に専念）
  api/            # Web用 Hono Worker（React から呼ばれるHTTP API）
  web/            # React フロントエンド
packages/
  core/           # 共有サービス層
    quiz/         # クイズ・設問のCRUD、権限チェック
    play/         # 出題・正誤判定
    stats/        # 統計集計
    rate-limit/   # レート制限
    db/           # D1アクセス（drizzle-orm等のクエリ実装）
    types/        # 共有型定義
```

- npm workspaces（or pnpm workspaces）で `packages/core` を `apps/bot` と `apps/api` の両方から依存させる
- `packages/core` の関数は D1 バインディング（`D1Database`）を引数として受け取る形にし、Worker環境に依存しないテスト可能な形で実装する
  ```ts
  // packages/core/quiz/createQuiz.ts
  export async function createQuiz(db: D1Database, input: CreateQuizInput, actor: Actor): Promise<Quiz> { ... }
  ```
- `apps/bot` と `apps/api` はそれぞれの `wrangler.toml` で同じ D1 データベースIDにバインドする

## 認証の扱い

サービス層の関数は「誰が呼んでいるか（`Actor`: user_id / guild_id）」を引数で受け取るだけで、認証方式そのものは知らない。認証はそれぞれのWorkerの入口で行い、`Actor` に変換してから `core` の関数に渡す。

- `apps/bot`: Discord Interactionのリクエスト署名検証（Discordの公開鍵で検証） → Interactionから `user_id` / `guild_id` を取得し `Actor` を構築
- `apps/api`: Discord OAuth2セッション（Cookie/JWT） → セッションから `user_id` を取得し `Actor` を構築（`guild_id` はリクエストパラメータやユーザーの参加サーバー一覧から解決）

## Web（React）との通信

React はブラウザ上で動くため `core` を直接importできない。`apps/api`（Hono）がHTTPエンドポイントとして `core` をラップして公開し、React はそのHTTP APIを呼ぶ。この部分のエンドポイント定義は [API設計.md](./API設計.md) を参照。

## まとめ図

```
Discord ── Interaction ──▶ apps/bot ──┐
                                        ├──▶ packages/core ──▶ D1
React ── HTTP ──▶ apps/api ───────────┘
```
