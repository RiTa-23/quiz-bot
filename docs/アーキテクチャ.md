# アーキテクチャ構成

[要件定義.md](./要件定義.md) を実現するためのシステム構成方針。

## 方針

Bot（Discord Hono）と Web用API（Hono）を独立した Cloudflare Worker として運用しつつ、両者が使うビジネスロジック（クイズCRUD・権限チェック・出題・正誤判定・統計集計・レート制限）は `core` パッケージとして共有ライブラリ化し、それぞれの Worker から直接 import する。HTTPで叩き合う共通APIとしては構成しない。

### この方針を採る理由

- Bot・Web APIともに Cloudflare Workers 上で動き、同じ D1 データベースにバインドする構成になるため、あえてHTTP（またはService Bindings）を挟む必要がない
- 共有ライブラリとして直接importすることで、関数呼び出しのレイテンシ・追加コストがゼロになる
- TypeScriptの型（Quiz, Question, Attempt など）とロジックを1箇所に集約でき、境界でのシリアライズ/デシリアライズのズレが発生しない
- 権限チェックをサービス層の関数内に内包させることで、呼び出し側（Bot/Web両方）での実装漏れを防げる

## モノレポ構成（案）

```
apps/
  bot/            # Discord Hono Worker（Discord Interactionの処理に専念）
  api/            # Web用 Hono Worker（React から呼ばれるHTTP API）
  web/            # React フロントエンド
packages/
  core/           # 共有サービス層
    quiz/         # クイズ・設問のCRUD、権限チェック
    play/         # 出題・正誤判定
    stats/        # 統計集計
    rate-limit/   # レート制限
    db/           # D1アクセス（drizzle-orm等のクエリ実装）
    types/        # 共有型定義
```

- npm workspaces（or pnpm workspaces）で `packages/core` を `apps/bot` と `apps/api` の両方から依存させる
- `packages/core` の関数は D1 バインディング（`D1Database`）を引数として受け取る形にし、Worker環境に依存しないテスト可能な形で実装する
  ```ts
  // packages/core/quiz/createQuiz.ts
  export async function createQuiz(db: D1Database, input: CreateQuizInput, actor: Actor): Promise<Quiz> { ... }
  ```
- `apps/bot` と `apps/api` はそれぞれの `wrangler.toml` で同じ D1 データベースIDにバインドする

## 認証の扱い

サービス層の関数は「誰が呼んでいるか（`Actor`: user_id / guild_id）」を引数で受け取るだけで、認証方式そのものは知らない。認証はそれぞれのWorkerの入口で行い、`Actor` に変換してから `core` の関数に渡す。

- `apps/bot`: Discord Interactionのリクエスト署名検証（Discordの公開鍵で検証） → Interactionから `user_id` / `guild_id` を取得し `Actor` を構築
- `apps/api`: Discord OAuth2セッション（Cookie/JWT） → セッションから `user_id` を取得し `Actor` を構築（`guild_id` はリクエストパラメータやユーザーの参加サーバー一覧から解決）

## Web（React）との通信

React はブラウザ上で動くため `core` を直接importできない。`apps/api`（Hono）がHTTPエンドポイントとして `core` をラップして公開し、React はそのHTTP APIを呼ぶ。この部分のエンドポイント定義は [API設計.md](./API設計.md) を参照。

## 出題セッションの状態管理（Durable Objects）

`/quiz play` の出題設定GUI・複数問セッション・早押しには、リクエストをまたいで保持する「進行状態」と、早押しの「最初の正解者」を競合なく確定する仕組みが必要になる。Cloudflare Workers はステートレスなため、これを **Durable Objects** で扱う。

### 採用理由

- **状態の保持**: 設定GUIの選択内容（クイズ・出題数・プレイ形式）、セッションの現在の問番号、参加者ごとのスコアを、Interactionをまたいで保持できる
- **原子的な早押し判定**: Durable Object は1インスタンスがリクエストを直列に処理するため、複数人が同時に回答ボタンを押しても「最初に正解した1人」を競合なく確定できる（ロックや外部トランザクション不要）
- **無料枠で完結**: SQLiteバックエンドのDurable Objectは Workers Free プランで利用可能。早押しはHTTP Interactionベースで成立するため **WebSocketは使わない**（詳細は [技術選定.md](./技術選定.md)）

### 配置

- `apps/bot` に `QuizSession` という Durable Object クラスを実装する（Bot Worker と同じデプロイに含める）
- **1つの出題セッション = 1つの DO インスタンス**。インスタンスキーはチャンネル単位（例: `guild_id:channel_id`）とし、同一チャンネルで同時に複数セッションが走らないようにする
- DO内のSQLiteストレージに以下を保持する
  - セッション設定（quiz_id, 出題数, mode, ホストuser_id）とクイズ選択GUIのページ位置
  - 進行状態（出題順の question_id リスト, 現在のindex, status: `draft`(設定中) / `active` / `finished`）
  - 早押しの回答受付状態（現在の問題で正解者が確定済みか）と、締め切りまでに回答した参加者・スコア（user_id → 獲得数）
- **早押しの制限時間（1問10分）は DO の `setAlarm` で管理する**。誰も正解しないまま10分経過したらalarmで締め切り、正解者なしとして次の問題へ進める
- 早押しの各設問が締め切られた時点で、その設問の回答結果（勝者・参加者）を `packages/core` 経由で D1 の `buzz_attempts` に書き込む（恒久記録。[DB設計.md](./DB設計.md) 参照）
- 1人モードは**回答のたびに**その1件を `packages/core` 経由で D1 の `quiz_attempts` に書き込む（`session_id` 付き）。セッションを途中で放棄しても記録が残る
  - この書き込みはユーザーのInteraction応答パス上にあるため、失敗してもプレイを止めずDO内のバッファに残し、次の回答時に再送する
  - セッション中の合計スコア表示自体は従来どおりDO内の状態から行う

### `packages/core` との関係

- クイズ・設問の取得や正誤判定など**ステートレスなロジックは従来どおり `packages/core`** を使う（`QuizSession` DO も内部で `core` を呼ぶ）
- DOが持つのは「セッションの進行状態」だけで、クイズ本体のデータ（D1）を二重に持たない
- **恒久的な記録**（`quiz_attempts`）は従来どおり `core` 経由でD1に書く。DOのSQLiteはセッション進行中の一時状態に用い、セッション終了後は破棄してよい

### モノレポ構成への追記

```
apps/
  bot/
    src/
      commands/    # スラッシュコマンドの定義とディスパッチ
      session/     # QuizSession Durable Object と出題GUI/セッション進行のハンドラ
      authoring/   # 設問追加・クイズ削除のGUI（パネルとハンドラ）
      stats/       # 成績表示コマンドのGUIとメッセージ整形
```

`authoring/` と `stats/` は Durable Object を使わず、選択状態をコンポーネントの `custom_id` に埋め込んでメッセージから復元する軽量な方式をとっている（セッションのような進行状態を持たないため）。

## まとめ図

```
Discord ── Interaction ──▶ apps/bot ──┬──▶ packages/core ──▶ D1（クイズ本体・回答記録）
                                        └──▶ QuizSession (Durable Object)（設定GUI・セッション進行・早押し判定）
React ── HTTP ──▶ apps/api ──────────────▶ packages/core ──▶ D1
```
