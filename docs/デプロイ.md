# デプロイ手順

本番構成は3つのデプロイ先が1つのD1を共有する。

```
apps/bot  → Cloudflare Worker（Discord Interactions Endpoint）
apps/api  → Cloudflare Worker（Web用HTTP API + OAuth2）
apps/web  → Cloudflare Pages（React SPA）
                 └─ すべて同一の D1（quiz-bot-db, id: 655f6617-5f01-48ba-975b-2be2244d8cc1）を参照
```

## ドメイン方針（重要）

セッション Cookie は `SameSite=Lax`（`apps/api/src/auth.ts`）。そのため **Web と API は同一の登録ドメイン配下のサブドメイン**に置く。

```
web: quiz.example.com   （Cloudflare Pages のカスタムドメイン）
api: api.example.com    （Worker のカスタムドメイン）
```

- `quiz.example.com` と `api.example.com` は同一登録ドメイン `example.com` なので**同一サイト**扱いになり、`credentials: 'include'` の fetch でも Cookie が送られる
- `*.pages.dev` と `*.workers.dev` の組み合わせはクロスサイトになり、`SameSite=Lax` の Cookie が送られず**ログインが成立しない**ので使わない（どうしても使う場合は Cookie を `SameSite=None; Secure` に変える必要があるが、Safari 等の第三者 Cookie ブロックで不安定）

## 前提

- Cloudflare アカウントと、`wrangler login` 済みの端末（`bunx wrangler whoami` で確認）
- 独自ドメインの **DNS が Cloudflare 管理下**にあること（ネームサーバーが Cloudflare を向いている）
- Discord Developer Portal のアプリ（`apps/bot` で使っているものと同じでよい）

> このリポジトリの `apps/api` / `apps/bot` は `wrangler` を devDependency に持つ。`bun install` 後は `bunx wrangler ...` で実行する。

### ドメインの登録先が Vercel Domains ＋ apex が既存Vercelサイトの場合

このプロジェクトのドメインは **Vercel Domains で登録**しており、**apex（`example.com`）は既存の Vercel サイトが本番稼働中**。今回はそのサブドメイン（`quiz.example.com` / `api.example.com`）を使う。

前提の整理:
- **登録元（レジストラ）と DNS ホストは別にできる**。ドメインは Vercel Domains のまま（更新・所有もそのまま）、**ネームサーバー（NS）だけ Cloudflare に向ける**
- Workers / Pages のカスタムドメインは、その**ホスト名の DNS が Cloudflare で管理されていること**が条件。Cookie が `SameSite=Lax` である以上 API は Web と同じ登録ドメインのサブドメインに置く必要があり、そのサブドメインを Worker に割り当てるには DNS を Cloudflare に載せるしかない
- NS を移すとそのドメインの**全 DNS が Cloudflare 管理**になる。**apex の既存 Vercel サイトを止めないために、既存レコードを Cloudflare 側へ確実に再現してから NS を切り替える**

**無停止で移行する手順（この順番を守る）:**

1. **現状の DNS レコードを控える。** Vercel のダッシュボード（該当プロジェクト/ドメインの DNS 設定）で、apex とサブドメインの既存レコードを全て書き出す。典型的な Vercel サイトは次のような構成:
   - apex `@`: `A 76.76.21.21`（Vercel の anycast IP。値は Vercel の指示に従う）
   - `www`: `CNAME cname.vercel-dns.com`
   - その他（メールの `MX` / `TXT`、検証用 `TXT` など）があれば全て
2. Cloudflare ダッシュボード > **Add a site** でドメイン（`example.com`）を追加（Free プランで可）。Cloudflare が既存レコードを自動スキャンしてインポートする
3. **インポート結果を手順1の控えと突き合わせて確認**。抜けているレコードは手で追加する。特に **apex の Vercel 向けレコードは必ず存在させ、プロキシ状態を「DNS only（グレー雲）」にする**（オレンジ雲＝プロキシにすると Cloudflare が SSL を終端して Vercel と競合しやすい）
4. Cloudflare が提示する **2つのネームサーバー**（例 `xxx.ns.cloudflare.com`）を控える
5. **Vercel Domains の管理画面**で、そのドメインの NS を手順4の Cloudflare のもの（2つとも）に変更する
6. 反映（数分〜数時間）後、Cloudflare 上でゾーンが **Active** になる。この時点で apex は手順3で再現したレコード経由で従来どおり Vercel サイトを表示する（レコードを正しく移せていれば無停止）
7. 以降、`quiz.example.com`（Pages）と `api.example.com`（Worker）のカスタムドメインを Cloudflare 側で割り当てる（手順4・6 で後述）

> ドメインの**登録・更新自体は引き続き Vercel Domains**。変わるのは「DNS の帳簿の置き場所」だけ。apex の Vercel サイトは、手順3でレコードを正しく再現できていれば影響を受けない。心配なら NS 切替直後に apex（既存サイト）と `www` の表示を確認する。

## 1. D1（共有DB）

D1 は作成済み（`quiz-bot-db` / id `655f6617-...`）。`apps/api/wrangler.jsonc` と `apps/bot/wrangler.jsonc` の両方にこの id が入っている。

本番スキーマを最新化する（初回とマイグレーション追加時）:

```
cd apps/api
bunx wrangler d1 migrations apply quiz-bot-db --remote
```

> `--remote` を付けないとローカルの疑似DBに当たるだけで本番に反映されない。api / bot どちらのディレクトリから実行しても同じ本番DBに適用される。

## 2. KV 名前空間（セッションストア）

`apps/api` のセッションは Workers KV に保存する。名前空間を作り、id を `apps/api/wrangler.jsonc` の `<KV_NAMESPACE_ID>` に差し込む。

```
cd apps/api
bunx wrangler kv namespace create SESSIONS
# 出力される id を控えて wrangler.jsonc の kv_namespaces[0].id に貼る
```

## 3. api の本番シークレット・変数

OAuth2 のクレデンシャルはシークレットとして登録する（`wrangler.jsonc` には書かない）。

```
cd apps/api
bunx wrangler secret put DISCORD_CLIENT_ID       # Discord Developer Portal > OAuth2 > Client ID
bunx wrangler secret put DISCORD_CLIENT_SECRET   # 同 Client Secret
```

非シークレットの本番URLは `apps/api/wrangler.jsonc` の `vars` を本番値に更新してからデプロイする（現状はローカル開発用の値）:

```jsonc
"vars": {
  "ENVIRONMENT": "production",
  "WEB_ORIGIN": "https://quiz.example.com",
  "DISCORD_OAUTH_REDIRECT_URI": "https://api.example.com/auth/discord/callback"
}
```

- `WEB_ORIGIN` はコールバック完了後のリダイレクト先（＝Webのオリジン）。CORS 許可オリジンにもなる
- `DISCORD_OAUTH_REDIRECT_URI` は次の手順5で Discord 側にも同じ値を登録する

## 4. api をデプロイ

```
cd apps/api
bunx wrangler deploy
```

デプロイ後、ダッシュボードで **Workers のカスタムドメイン**として `api.example.com` を割り当てる（Triggers > Custom Domains）。

## 5. Discord OAuth2 リダイレクトURIを登録

Discord Developer Portal > 対象アプリ > **OAuth2 > Redirects** に、手順3で設定した値と**完全一致**するURLを追加する。

```
https://api.example.com/auth/discord/callback
```

> 末尾スラッシュや `http/https` の差でも弾かれる。手順3の `DISCORD_OAUTH_REDIRECT_URI` と1文字違わず揃えること。

## 6. web をビルドしてデプロイ

Web は API のオリジンをビルド時の環境変数 `VITE_API_ORIGIN` で埋め込む。

```
cd apps/web
VITE_API_ORIGIN=https://api.example.com bun run build
bunx wrangler pages deploy dist --project-name quiz-bot-web
```

- SPA ルーティング用の `public/_redirects`（`/* /index.html 200`）がビルドに含まれ、リロード時の404を防ぐ
- Pages 側で **カスタムドメイン** `quiz.example.com` を割り当てる
- CI で Pages を使う場合は、`VITE_API_ORIGIN` をビルド環境変数に設定する

## 7. bot をデプロイ（未実施なら）

cd apps/bot

- スラッシュコマンド定義を変えた場合のみ、グローバル登録を実行（`apps/bot` の `register` スクリプト。反映に最大1時間）

## デプロイ後の確認

1. `https://quiz.example.com` を開く → 未ログインなら Discord ログイン画面
2. 「Discordでログイン」→ 認可 → `https://quiz.example.com` に戻り、ヘッダーに自分のサーバー一覧が出る（＝`/api/me` と Cookie が効いている）
3. サーバーを選び、クイズ作成・設問追加・公開クイズ検索・統計表示が動く
4. Discord 側で `/quiz play` などが従来どおり動く（bot）

## つまずきやすい点

| 症状 | 原因・対処 |
|---|---|
| ログイン後に一覧が空 / 401 が続く | Web と API が別サイト（pages.dev × workers.dev）になっている。同一登録ドメインのサブドメインに揃える |
| コールバックで `invalid oauth state` | Cookie が保存/送信されていない。`WEB_ORIGIN`・カスタムドメイン・HTTPS を確認 |
| Discord が `redirect_uri` を拒否 | 手順3の `DISCORD_OAUTH_REDIRECT_URI` と手順5の Redirects URL が不一致 |
| API 呼び出しが CORS で失敗 | `WEB_ORIGIN` が実際のWebオリジンと不一致 |
| `no such table` | 手順1のマイグレーションを `--remote` で未適用 |
| リロードで404（Web） | `public/_redirects` がデプロイに含まれていない |
| NS切替後に既存 apex（Vercel）サイトが表示されない | apex/`www` の Vercel 向けレコードが Cloudflare に無い、またはオレンジ雲になっている。前提「無停止で移行する手順」3 を確認し、apex は `DNS only` にする |
