# クイズ共有 Discord Bot 要件定義

## 1. 概要

クイズを作成・出題・管理できる Discord Bot。作成したクイズは自サーバー内限定の身内クイズとしても、他サーバーへの個別共有としても運用できる。クイズの作成・編集・削除は Discord 上のコマンドだけでなく Web アプリからも行える。

### 技術スタック
- Bot: Discord Hono
- Deploy: Cloudflare Workers
- Web: React + Hono
- DB: Cloudflare D1

### システム構成方針
Bot（Discord Hono）と Web API（Hono）はそれぞれ別の Cloudflare Worker として動かすが、クイズCRUD・出題判定・統計集計・レート制限などのビジネスロジックは `core` パッケージとして共有ライブラリ化し、両 Worker から直接 import する（monorepo構成）。HTTPを介した共通APIとして呼び合う構成は採用しない。詳細は [アーキテクチャ.md](./アーキテクチャ.md) を参照。

## 2. 機能要件

### 2.1 クイズ作成
- 出題形式は以下の3種類から選択できる
  - **4択**（ボタン選択、Discord Components 使用）
  - **○×**（2択、ボタン選択）
  - **自由記述**（チャットでの回答を判定。複数の正解パターンを許容）
- 1つのクイズは複数の設問（Question）を持てる
- 各設問には以下を設定できる
  - 問題文
  - 出題形式（4択・○×・自由記述）
  - 選択肢（4択の場合）
  - 正解
  - 解説（任意、出題後に表示）
- クイズ全体には以下のメタ情報を持つ
  - タイトル
  - 説明
  - 作成者（Discordユーザー）
  - 作成元サーバー（Discordサーバー）
  - 公開設定（サーバー限定 / 個別共有先）

### 2.2 クイズ出題

`/quiz play`（引数なし）で出題設定GUIを開き、設定してからプレイを開始する。

#### 2.2.1 出題設定GUI

`/quiz play` を実行すると、コマンドを実行したチャンネル上に設定用のコンポーネント（GUI）が展開される。ユーザーは以下を設定してから **Play ボタン** で出題を開始する。

| 設定項目 | UI | 選択肢 | デフォルト |
|---|---|---|---|
| プレイするクイズ | プルダウン（String Select） | そのサーバーで出題可能なクイズ一覧 | 最初に登録されたクイズ |
| 出題数 | 「出題数を設定」ボタン → モーダルで数値入力 | 1〜そのクイズの設問数（最大50） | 1 |
| プレイ形式 | ボタン（トグル） | `1人` / `みんなで早押し` | 1人 |

- クイズ選択プルダウンには、そのサーバーで**出題可能**なクイズ（自サーバー作成 + 共有を受けたもの）を作成日時昇順で表示する
- Discordのプルダウン上限（25選択肢）を超える場合は**同一プルダウン内ページング**で対応する
  - 1ページに最大24件のクイズを表示し、25個目を「▶ 次のページ」項目にする（2ページ目以降は先頭に「◀ 前のページ」）
  - 各項目の値で `quiz:<id>`（クイズ選択）と `page:next` / `page:prev`（ページ送り）を区別し、ページ送り選択時は同じメッセージを更新して該当ページを表示する
  - 現在のページ位置はセッションのドラフト状態（Durable Object）に保持する
  - 将来クイズ数が非常に多くなった場合に備え、名前検索ボタンを追加する余地を残す
- 出題数のモーダル入力は 1〜（選択中クイズの設問数、ただし最大50）の範囲でバリデーションする
- 設定状態はセッションのドラフトとして保持し、Play押下時に確定する（状態保持の仕組みは [アーキテクチャ.md](./アーキテクチャ.md) 参照）

#### 2.2.2 プレイ形式

**1人モード**
- Play押下者本人がプレイする
- 指定した出題数ぶん、1問ずつ順に出題する。各問に回答すると次の問題へ進む
- 出題形式に応じた回答方法:
  - 4択: 選択肢ぶんのボタン
  - ○×: ⭕/❌ の2ボタン
  - 自由記述: 「回答する」ボタン → 押下でモーダル（テキスト入力）を表示
- 全問終了後にスコア（正答数）を表示する

**みんなで早押しモード**
- チャンネルの参加者全員が同じ出題メッセージに対して回答できる
- 1問ずつ出題し、**最初に正解した人が得点**する。誰かが正解した時点でその問題を締め切り、次の問題へ進む
- **1問あたりの制限時間は10分**。誰も正解しないまま10分経過したら、その問題は正解者なしで締め切り次の問題へ進む（Durable Object の `setAlarm` で実現）
- 出題数ぶん繰り返し、最後に参加者ごとの得点ランキングを表示する
- 「最初の正解」の判定は競合しないよう原子的に確定する（[アーキテクチャ.md](./アーキテクチャ.md) の Durable Objects 参照）
- 早押しの得点は**1人モードの成績とは別に記録**する（統計は 2.7 を参照）

> 補足1: Cloudflare Workers はHTTP Interactionsベースでチャットメッセージを直接受信しないため、自由記述の回答はチャット送信ではなくモーダル入力で受け取る。
> 補足2: 早押しはDiscordのボタン押下（HTTP Interaction）で成立するため、Bot⇔Discord間のWebSocketは使わない。リアルタイム性はDurable Objectの排他制御で担保する。

### 2.3 クイズ削除・編集（Discord コマンド）
- 作成者、またはクイズの編集権限を持つユーザーがコマンドから削除・編集可能
- 削除時は確認を挟む

### 2.4 Web アプリでのクイズ管理
- クイズの一覧表示・詳細確認
- クイズ・設問の作成・編集・削除
- 共同編集者の追加・削除（後述）

### 2.5 クイズの共同編集
- クイズごとに編集権限を持つ対象を指定できる
  - **サーバー指定**：指定した Discord サーバーのメンバー全員に編集権限
  - **ユーザー指定**：特定の Discord ユーザーに編集権限
- 権限レベル（例）
  - Owner（作成者、削除・共有設定変更含む全権限）
  - Editor（設問の追加・編集・削除は可能、共有設定や削除は不可）

### 2.6 クイズの共有・公開
- **デフォルト**：作成したサーバー限定（非公開）
- **個別サーバー共有**：作成者が特定の他サーバーを指定してクイズを共有できる
  - 共有されたサーバーはそのクイズを自サーバーで出題可能
  - 共有されたサーバー側からの編集は不可（別途 Editor 権限を付与しない限り）
- 全体公開（クイズストア的な一覧）は本フェーズでは対象外（将来拡張の可能性あり）

### 2.7 出題結果の統計表示
- 出題結果（回答履歴）を記録し、Web アプリで統計として表示する
- **1人モードと早押しモードの成績は別々に記録・集計する**（回答の性質が異なるため）
  - 1人モード（ソロ）：正誤の履歴を記録（`quiz_attempts`）
    - クイズ単位：正答率、出題回数、設問ごとの正答率
    - サーバー単位：サーバー内での正答率ランキング（ユーザー別）
    - ユーザー単位：自分の解答履歴・正答率
  - 早押しモード：セッションごとの回答結果を別テーブルに記録（`buzz_attempts`、[DB設計.md](./DB設計.md) 参照）
    - サーバー単位：早押しの獲得数（最初に正解した回数）ランキング
    - ユーザー単位：早押しの参加数・獲得数

### 2.8 レート制限・不正回答対策
- **出題コマンドのレート制限**：同一ユーザー・同一サーバーからの連続出題をクールダウンで制限（例：一定秒数に1回まで）
- **回答のレート制限**：自由記述回答の連投・スパムを防ぐため、1設問に対する回答試行回数や間隔を制限
- **不正回答対策**
  - 出題中の問題の正解を、同一メッセージ・埋め込み内に含めない（別コンポーネント/DBのみに保持）
  - 自由記述の正解文字列は API レスポンスに含めない（判定はサーバー側のみで実施）
  - 同一ユーザーが同一設問に対して正解後に再回答できないようにする（1設問1回まで）

## 3. 認証・権限

- Web アプリは **Discord OAuth2** でログイン
- ログイン後、Discord アカウントの ID を軸に以下を判定
  - 自分が作成したクイズ
  - 自分が所属するサーバーが作成 or 共有を受けているクイズ
  - 自分が Editor として指定されているクイズ
- Bot 側のコマンド実行者も Discord ユーザー ID / サーバー ID をもとに同様の権限チェックを行う

### 権限マトリクス（案）

| 操作 | Owner | Editor | 共有先サーバーメンバー | その他 |
|---|---|---|---|---|
| 出題 | ○ | ○ | ○ | × |
| 設問の追加・編集 | ○ | ○ | × | × |
| クイズ削除 | ○ | × | × | × |
| 共有設定変更 | ○ | × | × | × |
| 共同編集者の追加・削除 | ○ | × | × | × |

## 5. 未確定事項 / 今後の検討

- クイズ削除の確認フロー（Discord 上でのボタン確認 UI）
- Editor 権限の粒度を将来増やすか（例：共有権限のみ付与できる Manager role 等）
- レート制限の閾値は初期実装時の暫定値（出題: 10秒に1回、回答送信: 5秒に3回まで）。運用しながら調整する（[技術選定.md](./技術選定.md) 参照）

- 自由記述の正規化ルール: トリム・小文字化・全角英数記号の半角化・全角スペースの半角化を行った上で完全一致判定する（`packages/core/src/play/normalizeAnswer.ts`）
