# クイズ共有 Discord Bot 要件定義

## 1. 概要

クイズを作成・出題・管理できる Discord Bot。作成したクイズは自サーバー内限定の身内クイズとしても、他サーバーへの個別共有としても運用できる。クイズの作成・編集・削除は Discord 上のコマンドだけでなく Web アプリからも行える。

### 技術スタック
- Bot: Discord Hono
- Deploy: Cloudflare Workers
- Web: React + Hono
- DB: Cloudflare D1

### システム構成方針
Bot（Discord Hono）と Web API（Hono）はそれぞれ別の Cloudflare Worker として動かすが、クイズCRUD・出題判定・統計集計・レート制限などのビジネスロジックは `core` パッケージとして共有ライブラリ化し、両 Worker から直接 import する（monorepo構成）。HTTPを介した共通APIとして呼び合う構成は採用しない。詳細は [アーキテクチャ.md](./アーキテクチャ.md) を参照。

## 2. 機能要件

### 2.1 クイズ作成
- 出題形式は以下の3種類から選択できる
  - **4択**（ボタン選択、Discord Components 使用）
  - **○×**（2択、ボタン選択）
  - **自由記述**（チャットでの回答を判定。複数の正解パターンを許容）
- 1つのクイズは複数の設問（Question）を持てる
- 各設問には以下を設定できる
  - 問題文
  - 出題形式（4択・○×・自由記述）
  - 選択肢（4択の場合）
  - 正解
  - 解説（任意、出題後に表示）
- クイズ全体には以下のメタ情報を持つ
  - タイトル
  - 説明（Bot側では、作成完了メッセージ・各GUIパネル・クイズ選択プルダウンの各項目に表示する。Webでは一覧・詳細に表示）
  - 作成者（Discordユーザー）
  - 作成元サーバー（Discordサーバー）
  - 公開設定（サーバー限定 / 個別共有先）
- **設問の追加はGUIで行う**。`/quiz add-question`（引数なし）でパネルを開き、クイズと出題形式をプルダウンで選び、「設問を入力」ボタンから開くモーダルで問題文・選択肢・正解・解説を入力する
  - クイズのプルダウンには、実行者が編集できるクイズ（Owner または Editor）のみを表示する（共有先サーバーは編集不可）
  - 出題形式に応じて入力方法が変わる
    - 4択: モーダルで選択肢（カンマ区切り）と正解を入力
    - ○×: **正解はパネル上の ⭕/❌ ボタンで選択**（モーダルには正解欄を出さない）。モーダルは問題文・解説のみ
    - 自由記述: モーダルで正解パターン（カンマ区切り）を入力

### 2.2 クイズ出題

`/quiz play`（引数なし）で出題設定GUIを開き、設定してからプレイを開始する。

#### 2.2.1 出題設定GUI

`/quiz play` を実行すると、コマンドを実行したチャンネル上に設定用のコンポーネント（GUI）が展開される。ユーザーは以下を設定してから **Play ボタン** で出題を開始する。

| 設定項目 | UI | 選択肢 | デフォルト |
|---|---|---|---|
| プレイするクイズ | プルダウン（String Select） | そのサーバーで出題可能なクイズ一覧 | 最初に登録されたクイズ |
| 出題数 | プルダウン（String Select） | 1〜そのクイズの設問数（最大50） | 1 |
| プレイ形式 | ボタン（トグル） | `1人` / `みんなで早押し` | 1人 |

- クイズ選択プルダウンには、そのサーバーで**出題可能**なクイズ（自サーバー作成 + 共有を受けたもの）を作成日時昇順で表示する
- Discordのプルダウン上限（25選択肢）を超える場合は**ページング**で対応する
  - 1ページに最大25件のクイズをプルダウンに表示する
  - プルダウンとは別に「◀ 前へ」「次へ ▶」ボタンを置き、ページを送ると同じメッセージを更新して該当ページのプルダウンを表示する（先頭/末尾ページでは各ボタンを無効化）
  - 現在のページ位置はセッションのドラフト状態（Durable Object）に保持する
  - 将来クイズ数が非常に多くなった場合に備え、名前検索ボタンを追加する余地を残す
- 出題数はプルダウンで選択し、**選択と同時にパネルへ即時反映**される
  - 選択肢は選択中クイズの設問数を上限に生成する（Discordのプルダウン上限25件に収めるため、1〜10は1刻み、以降は5刻みの区切り値＋上限値そのもの）
  - クイズを切り替えて設問数が減った場合、出題数は自動的に新しい上限まで丸められる
- 設定状態はセッションのドラフトとして保持し、Play押下時に確定する（状態保持の仕組みは [アーキテクチャ.md](./アーキテクチャ.md) 参照）

#### 2.2.2 プレイ形式

**1人モード**
- Play押下者本人がプレイする
- 指定した出題数ぶん、1問ずつ順に出題する。各問に回答すると次の問題へ進む
- 出題形式に応じた回答方法:
  - 4択: 選択肢ぶんのボタン
  - ○×: ⭕/❌ の2ボタン
  - 自由記述: 「回答する」ボタン → 押下でモーダル（テキスト入力）を表示
- 全問終了後にスコア（正答数）を表示する

**みんなで早押しモード**
- チャンネルの参加者全員が同じ出題メッセージに対して回答できる
- 1問ずつ出題し、**最初に正解した人が得点**する。誰かが正解した時点でその問題を締め切り、次の問題へ進む
- **1問あたりの制限時間は10分**。誰も正解しないまま10分経過したら、その問題は正解者なしで締め切り次の問題へ進む（Durable Object の `setAlarm` で実現）
- 出題数ぶん繰り返し、最後に参加者ごとの得点ランキングを表示する
- 「最初の正解」の判定は競合しないよう原子的に確定する（[アーキテクチャ.md](./アーキテクチャ.md) の Durable Objects 参照）
- 早押しの得点は**1人モードの成績とは別に記録**する（統計は 2.7 を参照）

> 補足1: Cloudflare Workers はHTTP Interactionsベースでチャットメッセージを直接受信しないため、自由記述の回答はチャット送信ではなくモーダル入力で受け取る。
> 補足2: 早押しはDiscordのボタン押下（HTTP Interaction）で成立するため、Bot⇔Discord間のWebSocketは使わない。リアルタイム性はDurable Objectの排他制御で担保する。

### 2.3 クイズ削除・編集（Discord コマンド）
- **削除はGUIで行う**。`/quiz delete`（引数なし）でパネルを開き、削除対象をプルダウンで選択する（IDの入力は不要）
  - プルダウンには**実行者が作成したクイズ（Owner）のみ**を表示する。権限マトリクス（3節）のとおり Editor はクイズ自体を削除できない
  - 削除ボタン押下後に**最終確認**を挟み、「本当に削除する」を押して初めて削除される（設問・共有設定・回答記録も連鎖削除される旨を明示）
- 設問の編集は Web アプリから行う（2.4）

### 2.4 Web アプリでのクイズ管理
- クイズの一覧表示・詳細確認
- クイズ・設問の作成・編集・削除
- 共同編集者の追加・削除（後述）

### 2.5 クイズの共同編集
- クイズごとに編集権限を持つ対象を指定できる
  - **サーバー指定**：指定した Discord サーバーのメンバー全員に編集権限
  - **ユーザー指定**：特定の Discord ユーザーに編集権限
- 権限レベル（例）
  - Owner（作成者、削除・共有設定変更含む全権限）
  - Editor（設問の追加・編集・削除は可能、共有設定や削除は不可）

### 2.6 クイズの共有・公開
- **デフォルト**：作成したサーバー限定（非公開）
- **個別サーバー共有**：作成者が特定の他サーバーを指定してクイズを共有できる
  - 共有されたサーバーはそのクイズを自サーバーで出題可能
  - 共有されたサーバー側からの編集は不可（別途 Editor 権限を付与しない限り）
- 全体公開（クイズストア的な一覧）は本フェーズでは対象外（将来拡張の可能性あり）

### 2.7 出題結果の統計表示
- 出題結果（回答履歴）を記録し、Web アプリで統計として表示する
- **1人モードと早押しモードの成績は別々に扱う**（回答の性質が異なるため）
  - 早押しモード：セッションごとの回答結果を `buzz_attempts` に記録（[DB設計.md](./DB設計.md) 参照）
    - サーバー単位：早押しの獲得数（最初に正解した回数）ランキング
    - ユーザー単位：早押しの参加数・獲得数
  - 1人モード（ソロ）：回答するたびに1設問1行を `quiz_attempts` に記録する（`session_id` 付き）
    - クイズ単位：正答率、出題回数、設問ごとの正答率
    - サーバー単位：サーバー内での正答率ランキング（ユーザー別）
    - ユーザー単位：自分の解答履歴・正答率
    - 同じクイズを繰り返しプレイできるよう、「同一設問1回まで」の制約は**Webのプレビュー経由の回答にのみ**適用する（`session_id` が null の行）。ソロはセッションを跨げば何度でも記録される（[DB設計.md](./DB設計.md) 参照）
    - セッション途中で放棄しても、それまでに回答した分は記録に残る

**Discord上での閲覧（コマンド）**

Web アプリだけでなく、Discordのコマンドからも成績を見られる。いずれも**出力はチャンネルに公開**され、集計は**全期間**（期間の絞り込みUIは設けない）。

| コマンド | 内容 |
|---|---|
| `/quiz stats` | クイズ別の統計。プルダウンでクイズを選ぶと、全体の正答率・参加人数と設問ごとの正答率を表示する。**このサーバー分のみ**を集計し、まだ誰も答えていない設問も一覧に出す（`—` 表示） |
| `/quiz my-stats` | 実行者の**このサーバーでの**成績（1人モードの回答数・正答率、早押しの回答数・獲得数、よく遊んだクイズ） |
| `/quiz ranking` | サーバー内ランキング。1人モードの正解数 TOP10 と早押しの獲得数 TOP10 |

- クイズ別統計は**閲覧権限のあるクイズのみ**（`assertCanView` 相当のチェックを `getQuizStats` 内部で行う）。共有クイズはサーバーごとに数字が変わる
- `/quiz my-stats` は**本人の成績のみ**で、他ユーザーを指定する手段は設けない
- ランキングにユーザーを並べても通知が飛ばないよう、メンションは解決させない（`allowed_mentions`）

**クイズ・設問が削除されたときの扱い**
- クイズを削除すると、そのクイズの回答記録（ソロ・早押しとも）も連鎖削除される（`ON DELETE CASCADE`）。設問を1件削除した場合も同様にその設問の記録が消える
- そのため、クイズを削除するとそこで得た正解数はサーバーランキング等から目減りする。これは意図した挙動として許容する（Discordの削除確認UIでも「回答記録もすべて削除され、元に戻せません」と警告している）

### 2.8 レート制限・不正回答対策
- **出題コマンドのレート制限**：同一ユーザー・同一サーバーからの連続出題をクールダウンで制限（例：一定秒数に1回まで）
- **回答のレート制限**：自由記述回答の連投・スパムを防ぐため、1設問に対する回答試行回数や間隔を制限
- **不正回答対策**
  - 出題中の問題の正解を、同一メッセージ・埋め込み内に含めない（別コンポーネント/DBのみに保持）
  - 自由記述の正解文字列は API レスポンスに含めない（判定はサーバー側のみで実施）
  - 同一ユーザーが同一設問に対して正解後に再回答できないようにする（1設問1回まで）
    - この制限はWebのプレビュー経由の回答に適用する。1人モードのセッション中は回答すると次の問題へ進むため同じ設問に再回答できず、セッションを跨いだ再挑戦は意図的に許可する（2.7参照）

## 3. 認証・権限

- Web アプリは **Discord OAuth2** でログイン
- ログイン後、Discord アカウントの ID を軸に以下を判定
  - 自分が作成したクイズ
  - 自分が所属するサーバーが作成 or 共有を受けているクイズ
  - 自分が Editor として指定されているクイズ
- Bot 側のコマンド実行者も Discord ユーザー ID / サーバー ID をもとに同様の権限チェックを行う

### 権限マトリクス（案）

| 操作 | Owner | Editor | 共有先サーバーメンバー | その他 |
|---|---|---|---|---|
| 出題 | ○ | ○ | ○ | × |
| 設問の追加・編集 | ○ | ○ | × | × |
| クイズ削除 | ○ | × | × | × |
| 共有設定変更 | ○ | × | × | × |
| 共同編集者の追加・削除 | ○ | × | × | × |

## 5. 未確定事項 / 今後の検討

- Editor 権限の粒度を将来増やすか（例：共有権限のみ付与できる Manager role 等）
- レート制限の閾値は初期実装時の暫定値（出題: 10秒に1回、回答送信: 5秒に3回まで）。運用しながら調整する（[技術選定.md](./技術選定.md) 参照）
- クイズ単位の正答率（`getQuizStats`）は、同じ人が繰り返しプレイするとその回数で重み付けされる。「ユニークユーザー基準」の集計が必要になったら別途対応する
- Web API用の `getUserStats` は**全サーバー横断**で集計する（Discord側はギルド内に限定した `getMemberStats` を使う）。ギルド絞り込みと早押しを含む形への拡張は今後の課題
- Web API に早押しランキングのエンドポイントが未実装（`getBuzzRanking` は core にあるが `apps/api` から呼ばれていない）

### 決定済み（実装時に確定）

- 自由記述の正規化ルール: トリム・小文字化・全角英数記号の半角化・全角スペースの半角化を行った上で完全一致判定する（`packages/core/src/play/normalizeAnswer.ts`）
- **Webログインの**セッションストア: Cloudflare Workers KV を採用（[技術選定.md](./技術選定.md) 参照）。出題セッションの進行状態はこれとは別で、Durable Object が保持する（[アーキテクチャ.md](./アーキテクチャ.md)）
- クイズ削除の確認フロー: `/quiz delete` のパネルで対象を選択後、最終確認ボタンを挟んで削除する（実装済み）
- ソロ成績の恒久記録: `quiz_attempts` に `session_id` 付きで1設問ごとに記録する（2.7参照）
- Discordでの成績閲覧: `/quiz stats` / `/quiz my-stats` / `/quiz ranking` の3サブコマンド（出力は公開・全期間・2.7参照）
